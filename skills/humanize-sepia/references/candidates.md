# 서로 다른 글 비교하기

여러 안을 요청했거나 서로 다른 핵심을 완성문으로 비교해야 할 때 사용한다. 기본 작업에 후보 생성을 추가하지 않는다.

## 의미가 다른 대안

각 방향에서 독자가 이해할 판단·배움과 이를 설명할 근거를 잡는다. 오래된 안내를 교체하고 수정일을 표시한 경험에서, 내용 갱신과 정보의 기준 시점을 알리는 표시는 전할 핵심이 다를 수 있다. 가상 예시의 사건을 현재 글로 가져오지 않는다.

읽고 알게 될 내용이 같다면 하나로 좁힌다. 역량 이름·단어·도입 순서만 바꾸며 후보 수를 늘리지 않는다. 요청한 수의 안은 각각 제공한다.

## 완성문 비교와 재구성

같은 자료·독자·목적·말투·분량으로 완성문을 쓴다. 고른 경험과 보호 내용은 유지한다. 기존 글 수정에서는 원문도 비교 대상이다. 필요한 판단과 조건이 드러나고 근거가 핵심을 설명하는 글을 기준으로 잡는다.

설명이 약하거나 중요한 내용이 흩어져 있으면 원자료를 보며 하나의 흐름으로 다시 써 본다. 다른 안의 유효한 근거나 연결은 활용하되 도입·배움·결론을 모두 붙이지 않는다. 후보에만 나타난 사실은 원자료로 확인하고 다른 역할·조건을 합쳐 사건이나 인과를 만들지 않는다.

새 글을 써 보는 결정과 채택하는 결정을 구분한다. 실제 문장에서 이해가 더 쉬워지고 필요한 근거·말투·조건이 남는 쪽을 채택한다. 대안이 낫지 않으면 기준 글을 쓴다. 본문만 요청하면 최종 글 하나를, 여러 안을 요청하면 각 안을 제공한다.

대안은 기본적으로 현재 문맥에서 작성한다. 별도 에이전트는 SKILL.md의 명시적 독립 생성 요청 기준을 따른다. 독립 생성을 요청받으면 같은 요청·자료·선호를 각 문맥에 제공하며 요청한 수를 넘기지 않는다. 후보 수·자기평가를 작문 우위나 실제 독자 평가로 세지 않는다.
