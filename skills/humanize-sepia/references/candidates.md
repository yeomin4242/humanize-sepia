# 서로 다른 글 비교하기

같은 자료에서 전할 핵심이나 근거의 해석이 달라질 때 완성문을 비교한다. 개선 요청에서는 바꿀 대목을 실제로 다시 써 보고, 원문과 비교해 최종 글을 선택한다.

## 비교할 내용 정하기

독자가 이 글에서 무엇을 이해해야 하는지 먼저 잡는다. 사용자 의도와 문항의 취지를 따르며, 같은 경험에서 서로 다른 핵심을 설명할 수 있는지 본다. 실제 판단, 여러 행동의 공통점, 독자가 놓치기 쉬운 조건처럼 자료로 설명할 수 있는 차이를 고른다.

예를 들어 오래된 안내문을 교체하고 수정일도 표시한 경험에서, “바뀐 내용을 반영한 작업”과 “독자가 정보의 기준 시점을 알 수 있도록 한 표시”는 전할 내용이 다르다. 이는 핵심의 차이를 설명하는 가상 예시이며 현재 글의 사실로 가져오지 않는다.

각 방향의 핵심과 이를 설명할 근거를 한 문장으로 잡아 비교한다. 읽고 알게 될 내용이 같다면 하나의 방향으로 좁힌다. 도입 위치나 역량 이름만 바꿔 별개의 관점으로 세지 않는다. 사용자가 고른 경험·입장·보호한 내용과 요청한 수정 범위는 유지한다.

## 완성문으로 비교하기

의미가 다른 방향이 있으면 각각 필요한 근거와 연결을 갖춘 본문으로 쓴다. 같은 자료·독자·목적·말투·분량 조건으로 비교하고 기존 글 수정에서는 원문도 함께 둔다. 대안은 현재 목적에 적합해야 하며, 차이를 만들려고 약한 글이나 자료에 없는 과거 사실을 넣지 않는다.

본문만 읽어 어떤 핵심이 남는지, 선택한 근거가 그 핵심을 어떻게 설명하는지 본다. 이번 목적에 필요한 판단과 조건이 드러나고 배경·반복이 이를 가리지 않는 쪽을 기준 글로 잡는다. 선택을 좌우한 구간과 이유는 작업 중에 짧게 확인하며 요청하지 않으면 출력하지 않는다. 길이·화려함·사실의 수·자체 점수로 선택하지 않는다.

방향이 분명한 짧은 글은 바로 쓴다. 표현만 수정하면 해당 구간을 다듬고, 검토만 요청하면 진단으로 끝낸다. 충분한 원문을 그대로 반환하라는 요청도 따른다.

## 개선안을 만들고 채택하기

**다시 써 볼지와 새 글을 채택할지를 구분한다.** 작성·개선 요청에서 핵심을 설명하는 관계가 약하거나 중요한 내용이 흩어져 있다면, 사실과 조건을 충족한 글에서도 실제 대안을 써 볼 수 있다. 원문이 오류 없이 읽힌다는 이유만으로 이 단계를 끝내지 않는다. 개선할 대목이 없거나 사용자가 허용한 범위를 벗어나면 기존 글을 쓴다.

기준 글에서 유지할 핵심, 보완할 설명, 덜어 낼 내용을 잡고 원자료를 보며 새 본문을 쓴다. 다른 후보의 근거나 연결이 도움이 되면 필요한 부분을 활용한다. 여러 글의 도입·배움·결론을 모두 담기보다, 하나의 핵심을 설명하는 흐름을 만든다. 같은 의미를 반복하는 마무리는 합치고, 추가한 설명이 독자의 이해에 무엇을 더하는지 본다.

원자료와 최신 요청을 사실의 기준으로 둔다. 후보에만 등장하는 사실은 확인한 뒤 사용한다. 다른 역할·조건·경험을 합쳐 새로운 사건이나 인과를 만들지 않는다. 당시 이유가 없으면 제공된 행동의 현재 의미를 설명하고 과거 동기를 보충하지 않는다.

새 본문과 기준 글을 같은 분량 조건에서 비교한다. 어떤 이해가 더 분명해졌는지 실제 문장으로 설명할 수 있고, 필요한 근거·말투·조건이 유지된 쪽을 채택한다. 새 글이 더 낫지 않으면 기준 글을 쓰고 기존 글 수정에서는 원문도 다시 확인한다. 좋은 원문을 유지하는 결정은 대안의 채택을 강제하지 않는다는 뜻이다. 비판적 개선의 반복 여부는 [비판과 반복 수정](improving.md#끝내기)를 따른다.

## 요청한 결과로 마무리하기

본문만 요청하면 최종 글 하나만 보여 준다. 여러 안을 보여 달라고 요청하면 각 안을 제공하고, 합쳐 달라는 요청이 없으면 하나로 합치지 않는다.

별도 작성 문맥을 요청받으면 각 문맥에 같은 요청·원자료·필요한 선호를 제공한다. 같은 문맥에서 쓴 대안을 독립 생성으로 보고하지 않는다. 일반적인 사용에 추가 모델 호출이나 별도 에이전트를 필수로 두지 않는다. 후보 수나 모델의 선택 이유를 실제 독자의 평가나 작문 우위로 표현하지 않는다.
