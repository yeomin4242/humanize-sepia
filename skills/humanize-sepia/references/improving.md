# 비판과 반복 수정

이미 쓴 글을 목적에 맞게 개선하는 `improve` 작업의 기준이다. 독자가 쉽게 납득하지 않는다는 가정으로 주장과 근거를 살펴보고, 실제로 문제가 있는 부분을 고친 뒤 다시 확인한다. 문제가 글과 요청에서 확인될 때 수정하고, 그 문제가 해결됐는지는 수정본으로 판단한다.

## 방향과 기준점

먼저 누구에게 무엇을 전달하려는지, 글이 어떤 역할을 해야 하는지 정한다. 자기소개서는 [문항이 확인하려는 내용](applications.md)과 작성자가 원하는 경험을 함께 읽는다. 문항이 없다면 주어진 글과 요청에서 목적을 파악하고, 새로운 평가 항목을 가정하지 않는다.

이번 요청의 원문·사실 자료·수정 조건을 기준점으로 삼는다. 반복 중에도 이 기준점과 비교한다. 이전 수정본만 기준으로 삼아 사실이나 말투가 조금씩 달라지는 일을 막는다. 사용자가 후속 요청에서 자료나 조건을 바꾸면 그 내용을 반영해 기준점을 갱신한다.

사용자가 지정한 경험과 메시지를 우선한다. 현재 글의 강조점이 문항의 취지나 독자의 필요와 어긋나면 표현을 고치기 전에 방향부터 짚는다. 같은 경험에서 목적에 맞는 주장과 근거를 다시 고르고, 보여 줄 수 없는 역량이나 과장된 주장은 실제 행동으로 뒷받침되는 범위로 조정한다. 경험이나 핵심 입장을 바꿔야 한다면 이유와 필요한 판단을 알린다. 원문에 적힌 사실은 별도 자료와 충돌하지 않는 한 작성자가 제공한 내용으로 삼는다.

## 비판할 부분 찾기

독자의 입장에서 다음을 확인한다. 자기소개서에만 필요한 항목은 해당 글에서 적용한다.

- 문항이 확인하려는 내용과 정해진 요구에 실제로 답하는가? 회사나 직무의 이름을 붙였을 뿐인 연결은 아닌가?
- 중요한 주장에 이를 뒷받침하는 행동과 근거가 있는가? 근거가 보여 주는 것보다 주장을 크게 쓰지 않았는가?
- 본인이 한 일, 타인의 승인, 팀 전체의 결과가 구별되는가? 사건의 순서를 성과의 원인으로 단정하지 않았는가?
- 판단과 행동을 이해하는 데 필요한 설명이 있는가? 글 안에서 주장·조건·시점이 서로 충돌하지 않는가?
- 중요한 내용이 배경이나 반복 설명에 가려져 있는가? 이 문장이 독자가 판단하는 데 무엇을 더해 주는가?

지적마다 해당 구간, 어떤 문제가 있는지, 자료나 요청의 근거, 독자가 이해하거나 판단하는 데 미치는 영향을 짚는다. “임팩트가 약하다”, “더 차별화해야 한다” 같은 평가만으로 수정을 시작하지 않는다. 이미 해결한 문제는 다시 제기하지 않고 새 문제나 남은 문제를 구체적으로 확인한다.

사실의 충돌과 요구 누락은 먼저 해결한다. 논리가 끊기는 부분과 중요한 행동이 잘 보이지 않는 문제를 그다음에 다루고, 표현 취향은 실제 문제와 구분한다. 다른 해석이 가능하거나 문체가 평범하다는 사실만으로 결함으로 세지 않는다. 독자가 할 수 있는 반론은 글의 주장과 근거에서 도출하고, 실제로 있었던 반대 의견이나 상황처럼 서술하지 않는다. 공개되지 않은 기업의 채점 기준을 비판의 근거로 삼지 않는다.

## 수정하고 다시 확인하기

1. **비판한다.** 위 기준으로 현재 글의 중요한 문제를 찾고, 고치려는 이유를 정한다. 검토만 요청했다면 문제·근거·개선 방향을 제공하고 여기서 끝낸다.
2. **수정한다.** 자료에 있는 행동과 근거를 활용해 문제를 해결한다. 필요하면 막연한 주장을 좁히고, 설명의 순서를 바꾸거나 군더더기를 줄인다. 문장만 고치거나 전개 순서를 유지하라는 조건이 있으면 그 범위에서 수정한다. 사실·작성 의도·말투·보호 구간은 [글 다듬기 기준](editing.md)을 따른다.
3. **재검토한다.** 비판한 문제가 실제 본문에서 해결됐는지 확인한다. 수정 과정에서 새 사실을 넣거나, 필요한 조건을 지우거나, 요청과 자료를 벗어난 주장으로 바꾸지 않았는지도 기준점과 대조한다. 문제가 남으면 무엇이 해결되지 않았는지 짚고 다음 수정을 진행한다.

비판과 수정은 서로 구분해 수행하지만, 같은 작성자가 두 단계를 수행했다면 독립적인 평가라고 보고하지 않는다. 수정본을 자기 점수로 높게 평가하거나 더 매끈해졌다는 이유만으로 받아들이지 않는다. 해당 문제의 해결과 사실 보존을 확인하고, 더 나아지지 않은 수정은 직전의 확인된 글로 되돌린다.

부족한 정보는 문장으로 꾸며 채우지 않는다. 측정하지 않은 성과, 제공되지 않은 과거 동기, 실행하지 않은 계획은 새 사실로 넣지 않는다. 확인된 자료로 주장 범위를 줄여도 요청을 충족할 수 있다면 그렇게 쓴다. 꼭 필요한 사실이 없으면 확인 질문이나 아직 답하지 못한 내용을 본문 밖에 남긴다. 질문만으로 문제가 해결됐다고 세지 않는다.

## 멈추는 기준

중요한 문제가 해결되고 요청 조건을 충족하면 끝낸다. 충분히 좋은 글은 수정 없이 마무리해도 된다. 기본은 한 차례 비판·수정·재검토이며, 해결 가능한 중요한 문제가 남았을 때만 반복한다. 별도 요청이 없으면 최대 세 차례 수정한다.

같은 문제를 다시 표현할 뿐이거나 더 좋아지지 않는다면 반복을 멈추고 가장 나은 확인된 글을 제공한다. 사용자 확인 없이는 해결할 수 없는 문제는 이유를 밝히고 남긴다. 문장 표현을 번갈아 바꾸거나, 새 결함을 만들어 반복을 이어가지 않는다.

결과는 개선한 본문을 먼저 보여 주고, 중요한 변화와 남은 확인 사항을 짧게 덧붙인다. 반복 횟수와 전체 비평 과정은 요청했을 때만 제공한다. 본문만 달라는 조건이면 그 형식을 따른다. 완성 여부는 실제 본문과 남은 문제로 설명하고, 검증하지 않은 품질 점수로 표현하지 않는다.
