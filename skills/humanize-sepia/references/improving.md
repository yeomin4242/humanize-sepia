# 비판과 수정

비판적 개선·독립 검토·복합 논리 문제에 사용한다. 작업 범위·종료·도구 사용은 SKILL.md의 검수 기준을 따른다.

## 비판을 확인하기

최신 요청·원자료를 사실과 조건의 기준, 수정 직전의 글을 이미 충족한 요구·근거·말투의 기준으로 둔다. 사용자나 실제 독자의 피드백을 우선하며 다음을 본다.

- 문항 대응: 취지와 필수 요구 충족 여부
- 주장 근거: 역할·성과·인과의 범위와 근거의 대응
- 판단 조건: 필요한 이유·조건의 보존
- 설명 흐름: 배경·반복이 핵심을 가리는 구간
- 전달력: 핵심을 행동·근거로 이해할 수 있는지, 문장 사이 관계를 독자가 추측해야 하는지

지적은 해당 문구·자료의 근거·막히는 이해·가능한 수정으로 연결한다. 명백한 오류, 작성자 확인이 필요한 사실, 선택 제안을 구분한다. 모호한 총평이나 다른 해석의 가능성만으로 결함을 만들지 않는다. 실제 세 요건·전문용어·기능 있는 연결은 패턴과 닮았다는 이유로 지적하지 않는다. 원문에만 있는 동기·시점도 충돌이 없으면 제공된 사실이다. 문제가 없으면 유지한다고 말하며 지적 수를 채우지 않는다.

빠진 내용은 문항의 필수 답변이거나 현재 주장에 필요한 근거인지 확인한다. 행동이나 시안만 설명한 글에 결과·성과가 없다는 이유로 결함을 만들지 않는다. 미확정 상태를 덧붙이면 오해가 해소되는 경우에도 필수 수정과 선택 제안을 구분한다.

## 실제로 고치기

사실·조건 문제를 먼저 고친다. 이어 효과가 큰 구간부터 삭제·병합·이동·교체한 실제 문장을 만든다. 구성 수정이 허용되고 설명이 흩어져 있으면 새 본문을 쓴 뒤 원문과 비교한다. 사실이 맞다는 이유만으로 개선안을 쓰기 전에 끝내지 않는다.

원인이 자료에 없으면 조치가 무엇을 확인하거나 구분하는지 설명해 행동 변화를 연결한다. 발생 원인을 만들어야만 이야기가 이어지는 것은 아니다. 조치의 완료 범위도 그대로 쓴다.

| 자료 | 활용할 설명 | 자료만으로 확정할 수 없는 내용 |
|---|---|---|
| 문서 검토 때 오래된 항목을 발견해 정정 | 검토로 발견한 항목과 실제 정정 내용 | 처음 작성할 때 검토하지 않아 오류가 발생했다는 원인 |
| 확인 절차를 메모하거나 체크리스트에 추가 | 다음 확인에 사용할 기준을 기록한 행동 | 이후 매번 실행했다는 습관·지속 사용 |

확인되지 않은 새 사실을 본문에 넣은 뒤 ‘다르면 알려 달라’고 설명하는 방식 대신, 확인된 행동으로 본문을 완성한다. 추가 사실이 핵심 답에 필요할 때만 본문 밖에서 확인한다.

어떤 이해가 쉬워졌는지 실제 문장으로 확인하고 필요한 근거·조건·말투를 보존한 수정을 채택한다. 대안이 낫지 않으면 직전 글로 돌아간다. 여러 핵심의 비교가 필요할 때만 [서로 다른 글 비교하기](candidates.md)를 읽는다.

반복이 문제였다면 같은 역할의 문장을 합쳤는지, 논리 비약이 문제였다면 연결에 필요한 근거가 보이는지, 말투가 문제였다면 원문의 어휘·격식·감정이 남는지 확인한다. 표현이 달라졌다는 사실만으로 해결했다고 보고하지 않는다. 사실 오류가 없는 글에서도 구성과 설명을 개선할 수 있으며, 효과가 없으면 좋은 원문을 유지한다.

## 끝내기

지적한 문제의 해결과 사실·조건·말투 보존을 확인하면 끝낸다. 추가 확인은 SKILL.md에서 허용한 범위에 한정한다. 표현 취향만으로 전체 검수를 반복하지 않는다. 남은 문제는 해당 문장·이유·필요한 정보로 밝히고, 추가 정보가 필요한 상태를 완료로 보고하지 않는다.

별도 검토를 요청받고 사용할 수 있을 때만 새 문맥에 요청·원자료·초안·필요한 선호를 전달한다. 작성자의 자기평가는 제외한다. 같은 문맥의 검토와 AI의 독자 추정을 독립 평가·실제 독자 의견으로 보고하지 않는다.
