# 비판과 반복 수정

이미 쓴 글에서 독자가 이해하거나 납득하기 어려운 부분을 찾고, 타당한 지적만 수정으로 연결한다. 검토만 요청하면 진단 후 끝낸다.

## 기준점

독자·목적·작성 의도·수정 범위를 읽는다. 지원서는 [문항의 취지](applications.md)를 함께 본다. 원자료와 최신 요청은 사실과 조건의 기준, 수정 직전의 확인된 글은 이미 충족한 요구·근거·말투의 기준으로 삼는다. 새 요청과 사실 정정이 있으면 갱신하고, 이전 수정본의 표현을 새 사실로 삼지 않는다.

사용자가 고른 경험과 메시지 안에서 적합한 주장과 근거를 먼저 찾는다. 근거보다 큰 주장과 목적에 어긋난 강조는 조정한다. 경험이나 핵심 입장을 바꿔야 한다면 이유와 필요한 판단을 알린다. 원문의 사실은 별도 자료와 충돌하지 않는 한 제공된 내용으로 삼는다.

## 독자가 막히는 부분

사용자나 실제 독자의 피드백이 있으면 어떤 문장의 어떤 이해 문제를 뜻하는지 먼저 확인한다. 수정 위치와 기대하는 변화로 옮기되, 글의 목적이나 사실과 어긋난 지적은 적용하지 않는다. 선호하는 수정과 그 이유도 함께 주어졌다면 [수정 취향 활용](preferences.md)을 참고한다.

독립적인 검토를 요청했거나 중요한 논리 문제를 별도로 확인할 필요가 있고 새 문맥이나 별도 검토자를 사용할 수 있다면, 원자료·최신 요청·초안과 필요한 선호 기준만 전달해 검토한다. 작성자의 구성안·자기평가·이전 비평은 제외한다. 검토자는 읽고 이해한 핵심과 근거를 짚고 아래 기준으로 의견을 돌려준다. 검토자에게 글을 다시 쓰거나 다른 자료를 찾게 하지 않는다. 실제 사용자·독자의 의견과 AI가 가정한 독자 반응을 구별한다.

새 문맥을 사용할 수 없으면 같은 작성 문맥에서 검토하되 독립 평가라고 표현하지 않는다. 스킬 파일을 읽었다는 사실만으로 별도 검토가 실행된 것은 아니다.

본문에서 이해한 핵심과 이를 뒷받침하는 내용을 짧게 짚은 뒤 다음을 확인한다.

- 문항의 취지와 명시한 요구에 답하는가? 회사·직무 이름만 붙인 연결은 아닌가?
- 행동과 근거가 주장을 뒷받침하는가? 역할·승인·실행·성과와 인과를 구별했는가?
- 판단과 행동을 이해하는 데 필요한 이유·조건이 있는가? 주장·시점이 충돌하지 않는가?
- 배경과 반복이 중요한 내용을 가리는가? 이 문장이 독자의 이해에 무엇을 더하는가?

지적에는 해당 문구, 원자료나 요청의 근거, 독자에게 막히는 점, 가능한 수정을 연결한다. 사실 충돌·요구 누락을 먼저, 논리와 강조를 그다음에 다룬다. 표현 취향은 선택 가능한 제안으로 구분한다. 결함 수를 목표로 삼거나 다른 해석의 가능성만으로 오류를 만들지 않는다. 반론은 글의 주장과 근거에서 도출하며 실제 과거 사건이나 공개되지 않은 기업 채점 기준으로 쓰지 않는다.

검토만 요청했다면 실제 문제와 선택 가능한 제안을 구분해 전달한다. 개선 요청에서는 객관적 오류가 없어도 강조와 연결을 더 분명하게 만드는 대안을 시험할 수 있다. 같은 뜻의 단어 교체만으로 개선했다고 판단하지 않으며, 좋은 원문은 유지할 수 있다.

## 지적을 수정으로 옮기기

자신이 만든 비판이나 전달받은 피드백이 요청·자료·본문에서 확인되는지 본다. “임팩트가 약하다”는 총평만으로 바꾸지 않는다. 성과 수치를 요구하는 지적은 문항에서 필요한지 확인하며, 확인된 반응으로 충분한 글도 인정한다.

| 지적 | 대응 |
|---|---|
| 사실 충돌·명시 조건 위반 | 자료와 요청에 맞게 고친다. |
| 중요한 논리·근거의 빈틈 | 어떤 이해가 막히는지 확인하고 제공된 내용으로 보완한다. |
| 작성자만 확인할 핵심 사실 | 필요한 정보와 해당 문장을 본문 밖에 남긴다. |
| 강조·연결·표현의 대안 | 허용한 수정 범위에서 실제 수정안을 써 보고 원문과 비교한다. 대안이 낫지 않으면 유지한다. |

사실·명시 조건의 문제를 고친 뒤, 독자의 이해에 효과가 큰 한두 구간부터 실제 수정안을 만든다. **대상 문구, 막히는 이해, 바꿀 방식, 수정 후 문장, 유지할 사실·조건**을 짧게 잡고 적용한다. 이 기록은 작업 중에 쓰며 요청하지 않은 과정 설명으로 출력하지 않는다.

| 바꿀 방식 | 실제로 만들 수정안 |
|---|---|
| 삭제 | 앞에서 전달한 판단을 되풀이하는 문장을 뺀 구간 |
| 병합 | 같은 의미의 두 설명을 필요한 근거와 함께 묶은 문장 |
| 이동 | 핵심 판단과 이를 설명하는 근거가 이어지도록 순서를 바꾼 구간 |
| 교체 | 자료에 있는 대상·차이·기준으로 추상적인 표현을 풀어 쓴 문장 |

구성까지 고쳐도 되는지 [편집 기준](editing.md)으로 확인한다. 표현만 수정하는 요청에서는 순서를 유지하며, 서로 다른 조건이나 역할을 합쳐 뜻을 바꾸지 않는다. 새 설명이 필요하면 자료로 뒷받침되는 현재의 해석을 쓰고 과거 사건과 동기는 원자료를 따른다.

중요한 설명이 흩어져 있거나 같은 자료를 다른 핵심으로 풀 수 있다면 [서로 다른 글 비교하기](candidates.md)로 완성문을 비교한다. 개선할 대목이 확인되면, 기존 글이 사실과 조건을 지키더라도 그 대목을 풀어 쓴 새 본문을 먼저 만든다. 원문 유지 여부는 실제 대안과 비교한 뒤 판단한다. 후보 비교와 재구성도 이번 수정에 포함하며, 별도의 반복 검토를 자동으로 시작하지 않는다.

수정안을 원문과 나란히 읽고 어떤 이해가 더 쉬워졌는지 확인한다. 필요한 근거가 살아 있고 연결이나 강조가 분명해진 쪽을 채택한다. 실제 수정안이 더 낫지 않으면 원문을 유지한다. 타당한 지적에 대응했다면 해당 문제를 풀었는지와 내용 보존을 따로 검사한다. 새 사실·과장·요구 누락이 없는지, 기존 근거와 이미 해결한 문제가 유지되는지도 확인한다.

개선한 이유를 해당 문장으로 설명할 수 있는 수정을 채택한다. 일부 변경만 잘못되면 그 부분을 복구하고, 전체가 나빠지면 직전의 확인된 글로 돌아간다. 길이·변경량·자체 점수 상승만으로 채택하지 않는다. [추가 표현을 빼고 원래 표현으로 돌려 보기](editing.md#최종-점검)를 적용하되 필요한 이유와 조건은 남긴다.

부족한 정보를 문장으로 꾸미지 않는다. 자료로 주장 범위를 좁혀도 요청을 충족하면 그렇게 쓴다. 꼭 필요한 사실은 질문이나 남은 한계로 본문 밖에 둔다. 같은 작성자가 검토했다면 독립 평가라고 보고하지 않는다.

## 끝내기

기본은 한 차례 비판·수정·재검토다. 중요한 문제가 해결되고 조건을 충족하면 끝낸다. 해결 가능한 문제가 남고 실제로 개선할 때만 반복하며, 별도 요청이 없으면 최대 세 차례 수정한다. 같은 문제를 다시 표현하거나 표현을 번갈아 바꾸게 되면 멈추고 가장 나은 확인된 글을 제공한다.

충분히 좋은 글은 그대로 둘 수 있다. 해결하지 못한 문제는 이유와 필요한 정보를 남긴다. 본문을 먼저 보여 주고 중요한 변화와 확인 사항만 덧붙이며 요청한 출력 형식이 우선이다.
