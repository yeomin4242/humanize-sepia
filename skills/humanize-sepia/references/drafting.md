# 자료로 글쓰기

여러 경험·요구에서 무엇을 남길지 판단하기 어려울 때 사용한다. 공통 사실·표현·출력 기준은 SKILL.md를 따른다.

## 쓸 내용과 그 관계 정하기

사용자가 고른 경험을 우선한다. 실제 행동·결과, 보여 주고 싶은 모습, 참고 예시를 구분한다. “리더십을 보여 주고 싶다”는 의도만으로 팀을 이끈 사실을 만들지 않는다.

각 요구에 필요한 근거, 이해에 필요한 배경, 덜어 낼 내용을 나눈다. 규모·직함보다 실제 기여와 독자의 필요로 고른다. 핵심을 역량 이름이 아닌 행동으로 설명할 수 있는 주장으로 잡는다.

근거의 관계는 조건, 선택의 차이, 확인된 인과, 여러 행동의 공통점에서 찾는다. 관계가 불분명하면 사실을 따로 설명하거나 덜 중요한 내용을 뺀다. “한 일 A·한 일 B·역량 C”보다 A와 B가 무엇을 설명하는지 연결한다. 마지막은 문항과 용도에 필요한 배움·판단·활용이 있을 때만 쓴다. 앞 내용을 재진술하는 칭찬·다짐을 붙이지 않는다.

“답변을 찾기 쉽도록 정리했다”는 행동 목적이고, “동료 두 명이 답변을 찾기 편해졌다고 했다”는 확인된 피드백이다. 목적만으로 효과 달성을 주장하지 않는다. 예상 효과는 자료에 있는 문제와 행동의 관계로 판단 이유를 설명하고, 확인된 결과와 구분한다. 성과·마무리의 공통 기준은 SKILL.md를 따른다.

같은 자료가 서로 다른 핵심을 뒷받침해 선택이 필요하다면 [서로 다른 글 비교하기](candidates.md)를 읽는다. 방향이 분명하면 바로 쓴다.

## 부족한 정보와 완성 여부

필수 답변이 빠졌다면 완성본과 구분하고 필요한 사실과 이유를 본문 밖에 밝힌다. 글을 완성할 수 있지만 중요한 판단이 약하다면, 답을 받았을 때 핵심이나 설명이 달라질 질문만 고른다. 방법을 바꾼 경험에는 다른 방법과 비교한 선택 기준을 물을 수 있다.

바로 작성하라는 요청이면 확인된 내용으로 쓰고, 당시 이유가 없으면 행동의 현재 의미를 설명한다. 주장하지 않은 성과의 미측정 여부까지 본문에 나열할 필요는 없다. 새 답은 사실의 기준에 반영하고 이미 적힌 내용을 다시 묻지 않는다.
