# 채널 적용

여러 채널로 전환하거나 독자·격식 기준을 조정할 때 사용한다. 기본 말투·형식·우선순위는 SKILL.md를 따른다.

## 전환할 내용

- 전달 목적: 경험 설명, 현황 공유, 승인 요청 등 현재 요청에 있는 목적 확인
- 독자 관계: 수신자와의 관계에 맞는 호칭·격식 선택
- 보존 내용: 사실·수치·역할·조건·효과의 근거 유지
- 행동 주체: 작성·확인·게시를 각각 실제 담당자에게 연결, 역할 전환 지점의 주체 명시
- 표현 조정: 문장 길이·문단·목록·인사 조정, 새로운 성과·감상·계획 추가 없이 전환

보고서의 명사형 문장을 메일에서 그대로 나열할 필요는 없다. 인사와 목적은 정중한 문장으로 쓰고, 병렬 현황·요청 항목은 개조식으로 정리한다. 블로그와 SNS의 해요체도 기본값이므로 사용자가 지정한 기록체·합니다체·반말을 우선한다. 요청하지 않은 승인·회신·기한을 메일에 추가하지 않는다.

## 연구계획서와 제안서

연구계획서는 연구 질문·현재 근거·방법·검증할 대상을 구분한다. 아직 수행하지 않은 실험·조사는 계획으로 쓰고, 가설·가능성·표본·한계의 범위를 유지한다. 기술 용어·변수명은 정확성을 우선하며, 새 연구 결과나 인용 출처를 만들어 구체화하지 않는다.

제안서는 해결할 문제·제안 내용·적용 조건·요청할 결정을 연결한다. 확인된 성과와 기대 효과를 구분하고, 승인·예산·일정이 정해지지 않았으면 확정된 실행 약속으로 쓰지 않는다. 기대 효과는 자료에 있는 근거와 가능성의 범위에서 설명한다. 자료에 없는 사후 설문·회신·보완 절차를 작성자의 약속으로 덧붙이지 않는다. 새 방안도 요청받은 경우에는 확정된 계획과 구분해 제안한다.

자료에 있는 계획의 끝에서 마무리해도 된다. 예를 들어 자료가 “초안 작성, 승인되면 다음 달 시범 적용”이면 “승인해 주시면 다음 달부터 시범 적용하겠습니다”로 쓴다. “의견을 받아 보완하겠습니다”, “결과를 공유하겠습니다”는 별도의 후속 업무이므로 자료나 추가 요청이 있을 때만 넣는다. 제안 글을 작성해 달라는 요청만으로 새 운영 절차까지 확정하지 않는다.

두 형식 모두 서식에서 요구한 항목·세 요건·병렬 구조는 지킨다. 모든 문장을 짧게 끊거나 전문용어를 일상어로 바꾸는 방식으로 자연스러움을 만들지 않는다.

## 같은 자료의 표현 예시

가상 자료: 질문·답변 안내표 작성, 매니저 확인 후 교대 동료들과 사용, 동료 두 명이 답변을 찾기 편해졌다고 응답. 문의 횟수는 미측정.

**업무 공유**

- 안내표 작성: 자주 들어오는 질문·답변 정리
- 사용 현황: 매니저 확인 후 교대 동료들과 사용
- 동료 피드백: 두 명이 답변을 찾기 편해졌다고 응답

**업무 메일**

> 매니저님, 확인해 주신 안내표를 교대 동료들과 함께 사용하고 있습니다. 동료 두 명은 답변을 찾기 편해졌다는 의견을 주었습니다.

**SNS**

> 자주 받는 질문과 답변을 표로 정리했어요. 매니저가 확인한 뒤 교대 동료들과 함께 사용했어요. 동료 두 명은 답변을 찾기 편해졌다고 말해 줬어요.

세 표현 모두 확인된 피드백만 전달한다. 문의 감소나 처리 시간 단축은 주장하지 않으므로 미측정 설명을 매번 붙일 필요는 없다. 이 예시는 채널 적용 설명이며 검증된 최적 문장이 아니다.

## 작성과 게시의 주체가 다른 경우

가상 자료: 본인이 신입 동료용 안내 초안의 준비물과 계정 신청 절차 정리. 담당 매니저가 확인·게시. 신입 동료 두 명이 준비물을 찾기 편해졌다고 응답.

- 업무 공유: `작성: 본인이 준비물·계정 신청 절차 정리`, `확인·게시: 담당 매니저`
- 업무 메일: “제가 작성한 안내 초안은 담당 매니저가 확인한 뒤 팀 문서함에 게시했습니다.”
- SNS: “준비물과 계정 신청 절차를 따로 정리했어요. 담당 매니저가 확인한 뒤 팀 문서함에 게시했어요.”

주체가 달라지는 곳만 명시해 읽는 흐름을 유지한다. 확인자가 게시자라는 사실이 없으면 두 역할을 합치지 않는다. 게시 주체가 불명확하면 “문서함에 게시됐습니다”처럼 행위자를 특정하지 않는 표현을 사용한다.
