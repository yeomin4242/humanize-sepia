# 채널 적용

채널·독자·격식을 조정할 때 읽는다. 공통 기준은 SKILL.md를 따른다.

## 전환할 내용

- 전달 목적: 경험 설명, 현황 공유, 승인 요청 등 현재 요청에 있는 목적 확인
- 독자 관계: 주어진 직책·호칭을 유지해 격식 조정. ‘부서장’ 같은 역할에서 ‘부장’ 같은 직급을 추정하지 않고, 정확한 호칭이 없으면 역할 명칭을 쓰거나 호칭 생략
- 표현 조정: 현재 요청의 범위에서 문장 길이·문단·목록·인사 조정

보고서의 명사형 문장을 메일에서 그대로 나열할 필요는 없다. 인사와 목적은 정중한 문장으로 쓰고, 병렬 현황·요청 항목은 개조식으로 정리한다. 본문만 문단 수를 지정했다면 인사·호칭은 그 문단 안에 넣거나 생략한다. 별도 제목·수신자 줄을 명시적으로 요청했다면 본문과 구분해 제공한다. 블로그와 SNS의 해요체도 기본값이므로 사용자가 지정한 기록체·합니다체·반말을 우선한다.

답장은 상대가 이미 전한 배경보다 결정·요청과 판단에 필요한 새 근거를 먼저 전한다. 사용자가 명시한 상태·실행 조건은 알고 있는 내용이어도 보존한다. 예의 있는 맺음말은 새 후속 연락·처리의 약속이 아니다. 방안 설계는 제안으로, 사용자가 직접 약속한 행동은 그 범위대로 쓴다.

## 연구계획서와 제안서

### 연구 질문과 조사 방법

선행 근거의 대상·조건·결과에서 아직 알 수 없는 점을 이번 질문과 잇는다. 문장 수와 배치는 설명에 맞춰 정한다. 조건 내 인과효과는 그대로 전한다. 논문 전체의 미조사나 업계 통념으로 넓히거나, 서로 다른 연구의 해석 차이를 다른 실험 효과의 원인으로 삼지 않는다.

**연구 목적만 한 문단**은 필요한 배경과 실제 알아볼 질문을 연결한다. 문장은 나눌 수 있으며, 일반 목적 예고나 질문의 기능 풀이를 겹치지 않는다. 요청한 해석 한계는 직접 밝히고 방법·표본·진행 상태는 요청 범위를 따른다.

가상 예:

> ‘완료’를 접수 종료로 읽은 발언과 전체 처리 종료로 읽은 발언이 함께 있다. 본 연구는 문구 안내와 설명 안내에서 어느 단계까지 끝났다고 읽는지, 증빙이 더 필요하다고 이해하는지와 필요하다면 무슨 증빙인지를 알아보고자 한다. 실제 증빙 제출 행동은 관찰하지 않는다.

가상 선행 연결:

> 김서영(2025)의 성인 40명 무작위 실험에서는 아이콘·문장 안내가 아이콘 안내보다 선택 오류를 줄였다. 제공된 결과로는 누가 문서를 볼 수 있다는 뜻으로 읽었는지 알 수 없어, 본 연구는 두 안내의 열람 대상 해석과 근거 표현을 알아보고자 한다.

방법은 제시·질문의 순서를 자료대로 쓴다. ‘각 안내를 본 뒤’가 각 안내 직후를 뜻하지는 않는다. 모호한 시점은 확정하지 않는다.

방법·한계의 가상 예:

> 성인 12명에게 이름 안내와 설명 안내를 차례로 보여 준 뒤, 각각 무엇을 기다린다는 뜻인지 묻는다. 전원 이름 안내부터 보므로 설명과 순서의 영향을 분리하기 어렵다. 승인 후 시작하며 현재 자료는 없다.

### 해석과 새 설계의 경계

| 내용 | 처리 |
|---|---|
| 뜻을 어떤 대상·상태·동작으로 읽는지 풀기, 기존 응답의 같음·다름 비교 | 같은 질문의 구체화이며 새 수집 절차가 아님 |
| 고정 순서 때문에 설명 효과와 순서 영향을 분리하기 어렵다는 한계 | 주어진 방법에서 도출되는 해석 조건으로 보존 |
| 왜·근거·첫 시선·망설임을 새로 수집 | 자료나 설계 보완 요청이 있어야 함 |
| 무작위 배정·시간 측정·새 코딩·검정 | 요청 범위의 보완안으로 제안과 확정 계획 구분 |

주어진 대상·질문·시점·순서는 보존한다. 각자 두 안내를 보는지, 한 안내만 보는 별도 집단인지에 따라 질문을 맞춘다. 순서가 자료에 없다는 이유로 실제 미정이라 단정하지 않는다. 균형 순서에 고정 순서 한계를 붙이거나, 정보가 같은 시안을 모든 조건의 통제로 확대하지 않는다.

### 필요한 한계와 질문 제안

방법 차이와 결론의 한계는 다르다. 선행 오류 감소 실험 뒤 뜻 면담을 계획했다면 ‘별도 오류 실험이 없으므로 오류 감소 효과를 재검증할 수는 없다’는 한계를 남긴다. 앞서 전한 면담 목적까지 다시 설명할 필요는 없다. 주장하지 않은 우수성을 부정하는 면책 대신, 독자의 해석을 바꾸는 조건을 남긴다. 승인 후 시작·자료 미수집·미채택 제안의 상태도 유지한다.

추가 질문은 바로 읽고 답할 문장으로 쓴다. 시점은 ‘두 안내를 모두 본 뒤’처럼 앞에 표시하고, 질문 뒤에는 새로운 적용 조건이나 요청받은 설계 이유만 붙인다. 예: 두 안내를 모두 본 뒤 “같은 상태를 각각 어떻게 이해하셨나요?” 질문에 차이를 전제하는 문제가 있으면 문구 자체를 고친다. 질문 수와 보완 범위(질문만/순서 설계까지)를 지킨다.

제안서는 독자가 판단할 제안 내용·이유·적용 조건·결정을 연결한다. 문제 상황이 자료에 없으면 제안의 실제 구성과 용도로 설명하고, 과거 불편이나 실패를 만들어 도입하지 않는다. 확인된 성과와 기대 효과, 승인 대기와 확정된 실행을 구분한다. 새 운영 방안을 설계할 때도 합의한 업무가 아닌 제안으로 표현한다.

### 승인 요청의 조건과 형식

현재 검토·승인 상태와 실행에 필요한 조건을 구분한다. 자료에 검토 완료와 사용 승인 대기가 함께 있으면 두 상태를 독자가 알 수 있게 쓴다. 사용 승인 요청만 남겨 대기 상태를 암시로 돌리지 않는다. 주어진 검토 주체와 현황은 그대로 쓰고, 이전의 요청·발송 이력은 자료에 있는 경우에만 쓴다. 이미 승인됐거나 검토만 마치면 실행하기로 합의한 경우에는 그 상태·조건대로 쓰고 새 승인을 요구하지 않는다. 실행 전 승인이 필요하다면 그 조건을 검토 완료로 바꾸지 않는다.

현황은 한 번 밝히고 실행 문장에 합의한 조건을 담는다. 상대에게 필요한 행동을 직접 요청한다. 검토 마무리가 목적이면 주어진 범위의 검토를 마쳐 달라고 쓰며, 완료 통보 요청만으로 그 행동을 대신하지 않는다. 승인·검토·회신 중 현재 요청의 동사를 따른다. 회신만 원하는 글에는 회신을 부탁하고 이미 완료된 검토를 다시 요청하지 않는다. 기능 설명은 독자가 대상·이유·범위를 이해하는 데 필요하고 자료의 구성으로 뒷받침될 때 보충한다. 같은 결정을 되풀이하거나 편의·성과·새 후속 약속으로 정중함을 보태지 않는다. 원문의 격식은 유지한다.

자료의 의미를 설명하는 것과 새 사실을 주장하는 것을 구별한다. ‘세 안내 항목을 한 표에 정리했다’는 자료에서 ‘한곳에서 확인할 수 있도록 구성했다’고 설명할 수 있다. ‘기존 안내가 흩어져 문제였다’는 별도 과거 사실이고, ‘반응을 모아 보완하겠다’는 별도 후속 약속이다. 각각을 뒷받침하는 자료나 현재 요청이 있을 때 사용한다.

두 형식 모두 서식에서 요구한 항목·세 요건·병렬 구조는 지킨다. 모든 문장을 짧게 끊거나 전문용어를 일상어로 바꾸는 방식으로 자연스러움을 만들지 않는다.

## 같은 자료의 표현 예시

가상 자료: 질문·답변 안내표 작성, 매니저 확인 후 교대 동료들과 사용, 동료 두 명이 답변을 찾기 편해졌다고 응답. 문의 횟수는 미측정.

**업무 공유**

- 안내표 작성: 자주 들어오는 질문·답변 정리
- 사용 현황: 매니저 확인 후 교대 동료들과 사용
- 동료 피드백: 두 명이 답변을 찾기 편해졌다고 응답

**업무 메일**

> 매니저님, 확인해 주신 안내표를 교대 동료들과 함께 사용하고 있습니다. 동료 두 명은 답변을 찾기 편해졌다는 의견을 주었습니다.

**SNS**

> 자주 받는 질문과 답변을 표로 정리했어요. 매니저가 확인한 뒤 교대 동료들과 함께 사용했어요. 동료 두 명은 답변을 찾기 편해졌다고 말해 줬어요.

세 표현 모두 확인된 피드백만 전달한다. 문의 감소나 처리 시간 단축은 주장하지 않으므로 미측정 설명을 매번 붙일 필요는 없다. 이 예시는 채널 적용 설명이며 검증된 최적 문장이 아니다.

## 작성과 게시의 주체가 다른 경우

가상 자료: 본인이 신입 동료용 안내 초안의 준비물과 계정 신청 절차 정리. 담당 매니저가 확인·게시. 신입 동료 두 명이 준비물을 찾기 편해졌다고 응답.

- 업무 공유: `작성: 본인이 준비물·계정 신청 절차 정리`, `확인·게시: 담당 매니저`
- 업무 메일: “제가 작성한 안내 초안은 담당 매니저가 확인한 뒤 게시했습니다.”
- SNS: “준비물과 계정 신청 절차를 정리했어요. 담당 매니저가 확인한 뒤 게시했어요.”

주체가 달라지는 곳만 명시해 읽는 흐름을 유지한다. 확인자가 게시자라는 사실이 없으면 두 역할을 합치지 않는다. 게시 주체가 불명확하면 “게시됐습니다”처럼 행위자를 특정하지 않는 표현을 사용한다.
