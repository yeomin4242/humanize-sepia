# 글 다듬기 기준

문장 구조를 고치며 뜻·말투·조건을 보존할 때 읽는다. 수정 범위와 기본 표현 기준은 SKILL.md를 따른다. 기계적인 반복과 문체 대조는 [자연스러운 표현](naturalness.md)을 참고한다.

## 필요한 수정 고르기

표현 수정에서는 독자의 이해를 막는 호응·수식·중복을 해당 구간에서 고친다. 명료한 긴 문장이나 거친 말투도 목적에 맞으면 살린다. 구성 수정 요청에서는 문단 이동·병합까지 수행하되, 단어만 바꿔 개선한 것처럼 끝내지 않는다. 과도한 압축으로 독자가 주체나 관계를 복원해야 한다면 필요한 설명을 남긴다.

## 보존할 내용

후속 수정은 새로 받은 글을 기준으로 하고, 새 글이 없으면 최근 완성문에 적용한다. 보호 구간은 원문에서 확인하고 줄 번호가 바뀌어도 내용을 유지한다. 타인의 직접 인용은 화자·문맥·출처와 표현을 보존한다. 사용자가 수정할 문장을 따옴표로 감싼 경우는 요청 범위에서 고친다.

누가 제안·결정·승인·실행했는지, 계획인지 완료인지, 의무인지 권고인지 확인한다. 수치가 같아도 대상·비교 기준이 달라지면 뜻이 달라진다. 일부 설명을 합치거나 삭제할 때 그 부분에만 있는 근거·예외·다음 행동을 남긴다.

| 원문 | 유지할 뜻 |
|---|---|
| 승인을 받으면 다음 달부터 적용할 예정이다. | 승인 조건과 아직 실행하지 않은 계획 |
| 문의가 줄었을 수 있지만 따로 측정하지 않았다. | 추정과 측정의 한계 |
| 담당자의 확인이 없는 요청은 처리하지 않는다. | 부정과 적용 조건 |
| 검토 결과를 팀장에게 전달했다. | 전달한 행동의 범위 |
| 나는 초안을 작성했고 매니저가 확인 후 게시했다. | 작성은 본인, 확인·게시는 매니저의 역할 |

코드 블록·인라인 코드·경로·URL·링크 대상·메타데이터는 문장 윤문에서 그대로 보존한다. 단어가 비슷하다는 이유로 변수·파일명·인용문까지 치환하지 않는다. 사용자가 해당 요소의 변경을 명시하면 그 범위만 수정한다.

## 문장 구조

협업·검토·성과·효율 등 통용 한자어는 유지한다. 전문용어를 설명할 때도 독자에게 필요한 뜻만 덧붙인다. 어휘 치환 때문에 역할·조건의 뜻이 달라지거나 문장이 길어지면 기존 용어를 쓴다. 목록 형식과 말투는 SKILL.md의 공통 기준을 따른다.

뜻을 바꾸지 않는 범위에서 겹친 명사화·이중 피동을 정리하고 주어와 서술어의 호응, 조사와 수식 범위를 맞춘다. 예를 들어 ‘검토를 진행했다’는 ‘검토했다’로, ‘판단되어질 수 있다’는 ‘판단될 수 있다’로 줄일 수 있다. 가능성·의무·권고·부정의 강도는 문장 길이보다 우선한다. ‘확인할 수 있다’를 ‘확인했다’로 바꾸면 행위의 상태까지 달라진다.

주어를 밝히거나 피동을 바꿀 때 자료에서 확인되는 주체만 쓴다. 긴 수식어는 대상 가까이에 두거나 문장으로 나눈다. “요청이 있으면 확인하고 회신한다”를 나눌 때도 두 행동에 걸린 조건을 남긴다. 같은 대상을 가리키는 용어는 일관되게 쓴다.

“매니저의 확인을 거쳐 게시했습니다”처럼 다른 사람의 확인 뒤에 작성자의 행동으로 읽히는 문장은 게시 주체를 원자료와 대조한다. 본인이 작성하고 매니저가 게시했다면 “제가 작성한 안내는 매니저가 확인 후 게시했습니다”로 구분한다. 주체가 확인되지 않으면 “안내가 게시됐습니다”처럼 행위자를 특정하지 않고, 핵심 답에 필요할 때만 확인한다.

## 최종 점검

새 문장을 원자료·최신 요청과 대조하고 수정 직전본의 필요한 근거와 말투를 확인한다. 일부 수정에만 문제가 있으면 해당 부분을 복구한다. 추가 표현을 빼거나 원래 표현으로 돌렸을 때 더 명료하면 덜어 내거나 되돌린다. 짧아진 양을 개선의 근거로 삼지 않는다. 뜻을 확정할 수 없으면 해당 문장과 필요한 정보를 밝힌다.
