# 수정 취향 활용

사용자가 실제로 채택한 수정, 수정 이유, 선호하는 글이 있을 때 이번 글의 선택 기준으로 활용한다. 모델이 만든 예시와 사용자가 선택하지 않은 이전 출력은 개인 취향의 증거가 아니다. 참고 자료가 없으면 현재 요청과 글의 목적에 맞춰 바로 작성한다.

## 무엇을 참고할지

현재 대화에서 확인된 선택이나 사용자가 참고하라고 제공한 글·파일을 사용한다. 원문과 수정본이 있으면 무엇이 바뀌었는지, 사용자가 왜 선호했는지, 어떤 독자·목적에서의 선택인지 함께 본다. 형용사로 말투를 요약하기보다 강조한 행동, 설명의 순서, 생략한 내용, 주장 강도의 차이를 살핀다.

사용자가 거절한 표현과 채택한 표현을 함께 주었다면, 이번 목적에 맞는 **거절한 문장→채택한 문장→선택 이유**를 짧은 대비 사례로 활용한다. 이유가 없으면 확인된 문장 차이만 참고하고 선호의 이유를 지어내지 않는다. 최종 문장만 따라 쓰는 대신 어떤 정보가 앞으로 왔고 무엇이 빠졌는지 본다. 대비 사례의 사건과 수치를 이번 글의 사실로 옮기지 않는다.

예를 들어 “책임감이 있다”는 선언을 구체적인 확인 행동으로 고친 경우, 사용자가 선호한 이유가 행동을 먼저 보여 주기 때문인지, 단순히 짧은 문장이 좋아서인지 구별한다. 이유를 모르면 한 문장의 수정에서 보편적인 취향을 확정하지 않는다. 이 예시는 읽는 방법을 설명하며 검증된 사용자 선호를 대신하지 않는다.

사용자가 명시한 선호는 해당 범위에서 따른다. 글에서 추론한 취향은 근거 문장과 적용 상황을 짧게 잡고, 다른 사례에서도 지지되는지 확인한다. 상황에만 필요한 선택을 “항상 이렇게 쓰기”로 바꾸지 않는다. 현재 요청이 바뀌면 현재 요청을 우선한다.

## 이번 글에 적용하기

현재 목적과 관련 있는 기준만 골라 핵심 선택·설명·표현에 활용한다. 참고 글의 문장과 모양을 그대로 복제하거나 경험·수치·감정·성과를 현재 글의 사실로 옮기지 않는다. 비슷한 말투와 더 명료한 내용은 별도로 확인한다. 작성자와 닮았다는 사실만으로 설득력이 높아졌다고 판단하지 않는다.

고친 글이 사용자가 선호한 선택을 반영하면서 현재 목적과 사실을 지키는지 확인한다. 충분히 좋은 원문은 유지하며, 과거 취향에 맞추기 위한 불필요한 수정을 하지 않는다.

## 다음 글에서도 활용할 때

파일을 읽거나 기록을 갱신해 달라는 요청이 있으면 지정한 경로를 사용한다. 기록에는 독자·목적, 실제 수정이나 근거 문장, 사용자가 밝힌 이유, 적용 범위만 필요한 만큼 남긴다. 개인 경험의 전체 내용을 공통 스킬 지침에 넣지 않는다. 새 요청으로 선호가 바뀌면 기록의 범위를 조정한다.

현재 대화와 제공된 기록 밖의 취향을 알고 있다고 표현하지 않는다. 스킬 설치만으로 다른 대화의 수정 기록이 자동 저장되거나 모델 자체가 학습되는 것은 아니다. 기록을 만들거나 재사용하는 과정은 사용자의 작업 요청에 맞춰 수행한다.
