# Humanize Sepia

[English](README.md) · [한국어](README.ko.md)

**경험·메모·초안으로 한국어 글을 쓰고 다듬는 스킬입니다.** 전하려는 내용과 읽을 사람을 바탕으로 자료를 고르고, 사실과 말투를 유지하면서 문장과 구성을 살피도록 돕습니다. 자기소개서, 업무 메일·보고서·제안서, 연구계획서 등에 사용할 수 있습니다.

버전 **0.4.2** · Codex / Claude Code · 지침과 예시는 주로 한국어로 작성돼 있습니다. 필요한 지침은 `skills/humanize-sepia` 폴더 안에 들어 있습니다.

## 할 수 있는 작업

| 작업 | 요청 예시 |
|---|---|
| 자료로 새 글 쓰기 | “이 경험과 메모로 내가 전하려는 말이 드러나게 써줘.” |
| 기존 글 다듬기 | “말투는 살리고 어색한 문장만 다듬어줘.” |
| 구성부터 다시 쓰기 | “사실과 의도는 유지하고 글의 흐름을 다시 잡아줘.” |
| 검토 의견 받기 | “글은 고치지 말고 문제 구간과 이유를 알려줘.” |
| 비판적으로 고치기 | “논리와 근거를 검토하고, 필요한 부분을 고친 뒤 다시 확인해줘.” |

하나의 스킬이 요청에 따라 작업 범위를 정합니다. 단순한 표현 수정에 여러 초안이나 별도 검토자를 기본으로 붙이지 않습니다. 작성·수정한 글은 사실·필수 답변·형식을 확인해 마칩니다. 비판적 개선은 검토·수정·재확인 한 차례로 진행하며, 추가 반복이나 독립 검토는 요청한 범위를 따릅니다.

자기소개서는 문항의 단어를 되풀이하기보다 실제로 확인하려는 내용을 경험의 판단·행동·근거로 설명하는 데 초점을 둡니다. 회사·직무 정보가 있으면 함께 참고하며, 필수 답변·사례 수·분량도 작성 조건으로 사용합니다.

## 작성과 수정의 기준

- 필수 답변과 선택적으로 활용할 자료를 구분합니다. 메모 전체를 옮기기보다 판단을 설명할 근거를 고릅니다.
- 본인의 행동과 동료의 역할, 검토와 승인, 계획과 실행, 실제 사용과 관측 효과를 구별합니다.
- 제공된 생각과 시점은 살리고, 자료에 없는 동기·성과·인과를 덧붙이지 않도록 안내합니다.
- 일반적인 태도 다짐과 구체적인 업무 약속을 구분합니다. 자료에 있는 계획은 유지하고, 요청받은 새 방안은 제안으로 표현합니다.
- 연구 글에서는 선행 결과와 새 질문, 주어진 방법과 결론의 한계를 구분합니다. 출처 없는 일반화로 필요성을 꾸미지 않습니다.
- 표현 수정은 원래의 뜻과 말투를, 구성 수정은 필요한 사실과 조건을 기준으로 삼습니다. 전문용어와 의미 있는 반복은 유지할 수 있습니다.
- 말투·형식은 현재 요청, 원문·참고 예문, 채널 기본값 순으로 정합니다. 본문만 요청하면 별도 제목이나 해설을 붙이지 않습니다.

0.4.2에서는 공통 지침과 참고 자료의 중복을 줄였습니다. 연구 글은 문장 수를 고정하기보다 질문·근거·한계의 관계를 살피도록 했습니다. 경험과 배움을 함께 묻고 순서가 자유로운 글에는 판단이 바뀐 지점에 배움을 두고 확인된 결과로 마치는 전개 예시를 제공합니다. 검토에서는 근거 없는 역할·성과 주장과 선택적인 표현 제안을 구분합니다.

자소서의 글자 수와 바이트 수는 구분하며 제출처의 계산 규칙을 우선합니다. 분량을 채우려고 없는 사실이나 빈 다짐을 추가하지 않도록 합니다. 정확한 분량 확인은 사용하는 도구의 지원 여부에 따라 달라집니다.

## 현재 확인한 범위와 한계

제한된 가상 사례 비교에서는 사실·역할·승인 상태·요청 형식을 지키는 결과를 확인했습니다. **스킬을 쓰지 않은 기본 모델이나 0.4.1보다 작문이 더 우수하다는 차이는 확인하지 못했습니다.** 0.4.2는 중복 지침과 입력 분량을 줄인 버전이며, 재요약이 발생하는 사례가 줄었다고 확인된 것은 아닙니다. 반복이나 추상적인 표현이 남을 수 있으며, 모든 입력에서 사실과 의도가 보존된다고 보장하지 않습니다.

모델별 작문 우위나 실행시간 개선도 확인된 기능으로 소개하지 않습니다. 표현 패턴은 수정할 부분을 찾는 단서로 사용하며, AI 작성 여부를 판별하거나 탐지기 통과를 보장하지 않습니다. 최종 글은 실제 경험·숫자·조건과 대조해 확인해 주세요.

## 설치

### Codex

Codex에서 다음과 같이 요청할 수 있습니다.

```text
$skill-installer https://github.com/yeomin4242/humanize-sepia/tree/v0.4.2/skills/humanize-sepia
```

직접 설치하려면 저장소를 받은 뒤 스킬 폴더를 복사합니다.

```bash
git clone --branch v0.4.2 --depth 1 https://github.com/yeomin4242/humanize-sepia.git
mkdir -p ~/.agents/skills
cp -R humanize-sepia/skills/humanize-sepia ~/.agents/skills/
```

프로젝트에서만 쓰려면 해당 프로젝트의 `.agents/skills/humanize-sepia`에 넣습니다.

### Claude Code

같은 저장소에서 스킬 폴더를 사용자 스킬 경로에 복사합니다.

```bash
mkdir -p ~/.claude/skills
cp -R humanize-sepia/skills/humanize-sepia ~/.claude/skills/
```

프로젝트에서만 쓰려면 `.claude/skills/humanize-sepia`에 넣습니다.

같은 이름의 전역 설치본과 프로젝트 설치본을 함께 두었다면, 실제 읽은 `SKILL.md` 경로와 버전을 요청해 어느 설치본을 썼는지 확인할 수 있습니다.

**업데이트할 때는 기존 설치 폴더를 먼저 다른 위치에 백업한 뒤 교체하세요.** 기존 폴더 안에 새 폴더를 중첩해 복사하지 않도록 주의하세요. 두 도구를 함께 쓴다면 각 설치본을 같은 버전으로 맞춥니다.

## 사용법

Codex에서는 `$humanize-sepia`, Claude Code에서는 `/humanize-sepia`로 호출하고 원하는 작업을 설명해 주세요. **정해진 입력 양식이나 순서는 없습니다.** 읽을 사람, 쓰고 싶은 방향, 문항·자료·경험·초안을 편하게 보내면 됩니다.

아래는 가상 경험을 사용한 예시입니다. Claude Code에서는 호출 부분을 `/humanize-sepia`로 바꿔 입력하세요.

```text
$humanize-sepia

온라인 장터의 판매자 지원 직무에 지원하려고 해.
문항은 “기존 방식과 다르게 접근해 문제를 해결한 경험”이야.

아르바이트하던 매장에서는 직원마다 안내가 달라 손님이 다시 묻곤 했어.
자주 들어오는 질문과 답변을 표로 정리했고, 매니저가 확인한 뒤
교대 동료들과 함께 사용했어. 동료 두 명은 답변을 찾기 편해졌다고 했어.
문의가 얼마나 줄었는지는 세어 보지 않았어.

동료들이 함께 참고할 기준을 만든 과정을 보여 주고 싶어.
초안의 “혁신적인 개선을 이루었다”는 표현은 너무 거창해 보여.
내가 한 일이 드러나게 담담한 말투로, 공백 포함 500자 이내로 써줘.
```

수정 범위를 구체적으로 말해도 됩니다.

```text
$humanize-sepia 내용과 말투는 유지하고 두 번째 문단만 짧게 다듬어줘.
숫자와 인용문은 바꾸지 말아줘.
글: …
```

```text
$humanize-sepia 글은 고치지 말고, 독자가 이해하기 어려운 부분을 짚어줘.
실제 오류와 선택적으로 바꿀 부분을 나눠 알려줘.
글: …
```

```text
$humanize-sepia 논리와 근거를 비판적으로 검토하고 필요한 부분을 고쳐줘.
수정 후에는 지적한 문제가 해결됐는지와 사실·조건이 유지됐는지 확인해줘.
글: …
```

이전에 직접 쓴 글이나 마음에 들게 고친 문장도 참고할 수 있습니다. 무엇이 좋았는지 함께 알려 주면 이번 글에 적용할 기준을 정하는 데 도움이 됩니다. 설치만으로 취향이나 수정 기록이 자동 저장되지는 않습니다. 다른 대화에서 쓰려면 필요한 기록을 다시 제공해 주세요.

### 모델별 지침

스킬에는 Sonnet 5.5, Opus 5.5, GPT-6.1 Sol, GPT-6 Sol, GPT-6 Luna, GPT-6 Astra용 지침이 포함돼 있습니다. **호스트가 정확한 현재 모델명을 제공하면 해당 지침 하나를 선택하도록 안내합니다.** 모델명을 알 수 없거나 목록에 없으면 공통 지침을 사용합니다. 이는 스킬의 지침 선택 규칙이며 모든 환경에서 자동 판별이 보장되는 기능은 아닙니다.

요청에 `모델 지침: gpt-6.1-sol`처럼 적어 수동 선택할 수도 있습니다. 실제 실행 모델이나 추론 강도를 바꾸지는 않습니다. 두 Sol 버전은 같은 지침을 사용합니다. 적용 여부를 확인하려면 “이번에 적용한 모델 지침과 선택 근거만 알려줘”라고 요청하세요.
