# Humanize Sepia

[English](README.md) · [한국어](README.ko.md)

**전하고 싶은 내용을 자연스러운 한국어 글로 씁니다.** 경험과 메모에서 쓸 내용을 고르고, 생각이 잘 이어지도록 문단을 구성합니다. 초안이 있다면 내용과 말투를 살려 다듬습니다. 자기소개서는 지원 회사와 직무를 고려해 문항이 무엇을 확인하려는지 파악하고, 그에 맞는 경험을 글로 풀어냅니다.

현재 버전은 **0.2.0**입니다. 지침과 예시는 한국어로 작성돼 있으며, 글쓰기에 필요한 기준은 `humanize-sepia` 폴더 안에 모두 들어 있습니다.

## 하는 일

| 원하는 작업 | 이렇게 요청하세요 |
|---|---|
| 자료로 글 완성하기 | “이 경험과 초안으로 내가 전하려는 말이 드러나게 써줘.” |
| 기존 글 다듬기 | “말투는 살리고 문장만 다듬어줘.” 또는 “구성부터 다시 잡아줘.” |
| 검토 의견 받기 | “글은 고치지 말고 부족한 부분과 이유를 알려줘.” |
| 비판적으로 개선하기 | “논리와 근거를 검토해서 필요한 부분을 고치고 다시 확인해줘.” |

하나의 스킬에서 원하는 결과와 수정 범위를 자연어로 파악합니다. `$humanize-sepia`에 편하게 요청하면 됩니다. 작성한 뒤 비판적으로 검토해 달라고 함께 요청할 수도 있습니다. 가벼운 문장 다듬기에는 반복 검토를 붙이지 않습니다.

글을 쓸 때는 무엇을 남길지 고르고, 자료 사이의 관계를 읽어 글로 풀어냅니다. 여러 활동을 나열하는 데 그치지 않고, 어떤 문제에 대응했는지와 그 과정에서 무엇을 이해했는지 연결합니다. 앞에서 한 말을 끝에서 다시 반복하는 부분은 합치거나 덜어 냅니다. 강조할 내용이나 설명 순서에 따라 전달이 달라진다면 서로 다른 구성으로 끝까지 써 보고 비교합니다. 한 글을 선택하거나, 각 글에서 필요한 장점을 살려 하나의 흐름으로 다시 씁니다. 다시 쓴 글이 더 낫지 않으면 이전 글을 유지합니다. 참고 예시는 선택의 차이를 보여 주며, 검증된 정답 문장이나 사용자 취향을 대신하지 않습니다.

자기소개서는 문항이 확인하려는 내용을 읽고, 그에 맞는 판단과 행동이 드러나게 씁니다. “다른 시각”을 묻는다면 문제의 어떤 점에 주목했고 왜 그 방법을 택했는지 보여 줍니다. 정해진 분량과 사례 수, 반드시 답하라고 한 내용도 지킵니다.

보여 주고 싶은 역량은 실제 경험을 바탕으로 씁니다. 내가 한 일, 다른 사람이 승인한 일, 팀 전체의 결과를 구분합니다. 중요한 사실이 빠져 있다면 필요한 부분만 묻거나 확인된 내용으로 초안을 먼저 씁니다. 선택한 이유처럼 답변을 더 잘 설명할 정보가 있다면 핵심 질문을 덧붙일 수 있습니다. 바로 작성하거나 본문만 달라는 요청을 우선하며, 확인할 내용은 본문 밖에 안내합니다.

## Codex 설치

Codex에서 다음과 같이 설치를 요청하세요.

```text
$skill-installer https://github.com/yeomin4242/humanize-sepia/tree/main/skills/humanize-sepia
```

직접 전역 설치하려면 저장소를 받은 뒤 스킬 폴더를 복사합니다. 같은 이름의 `humanize-sepia` 폴더가 이미 설치돼 있다면 먼저 다른 위치에 백업해 두세요.

```bash
git clone https://github.com/yeomin4242/humanize-sepia.git
mkdir -p ~/.agents/skills
cp -R humanize-sepia/skills/humanize-sepia ~/.agents/skills/
```

프로젝트에서만 쓰려면 해당 프로젝트의 `.agents/skills/humanize-sepia`에 스킬 폴더를 넣습니다.

## 사용법

`$humanize-sepia`를 쓰고 어떤 글을 쓰고 싶은지 편하게 설명해 주세요. 전하려는 말과 읽을 사람, 원하는 말투를 경험·메모·초안과 함께 보내면 됩니다. 자기소개서라면 회사 소개와 직무, 문항도 함께 보내 주세요. **정해진 양식이나 입력 순서는 없습니다.** “쓰고자 하는 방향”이라고 적어도 되고, 제목 없이 이어 써도 됩니다.

아래 기업과 경험은 사용법을 보여 주기 위한 가상 예시입니다.

```text
$humanize-sepia

작은 가게들이 입점하는 온라인 장터의 운영 담당자로 지원하려고 해.
판매자 문의에 답하고, 판매자들이 겪는 불편을 찾아 개선하는 일이래.
자소서 문항은 “기존 방식과 다르게 접근해 문제를 해결한 경험”이야.

아르바이트하던 매장에서는 직원마다 안내 내용이 달라서 손님이 같은
내용을 다시 묻곤 했어. 자주 들어오는 질문과 답변을 표로 정리했어.
매니저가 확인한 뒤 교대하는 동료들과 함께 사용하기 시작했고,
동료들은 답변을 찾기 편해졌다고 했어. 같은 질문이 얼마나 줄었는지는
따로 세어 보지 않았어.

안내 내용이 제각각이라는 점을 발견하고, 동료들이 함께 참고할 수 있는
표로 정리한 과정을 보여 주고 싶어.
초안에는 “남다른 관찰력으로 혁신적인 개선을 이루었다”고 썼는데,
너무 거창해 보여. 내가 한 일이 잘 드러나도록 자연스럽게 써줘.
공백 포함 500자 이내로, 담담한 말투면 좋겠어.
```

초안이 있다면 함께 보내 주세요. 쓸 만한 문장과 말투는 살리고, 전달하고 싶은 내용에 맞춰 글을 완성합니다. 뜻이나 중요한 사실이 달라질 수 있는 부분은 확인합니다. 먼저 질문을 받고 싶다면 “내 판단이 드러나려면 어떤 정보가 필요한지 하나만 먼저 물어봐 줘”라고 요청할 수 있습니다.

기존 글을 다듬거나 살펴보고 싶다면 이렇게 요청할 수 있습니다.

```text
$humanize-sepia 내용과 말투는 그대로 두고, 어색한 문장만 다듬어줘.
숫자와 인용문은 바꾸지 말아줘.
글: …
```

```text
$humanize-sepia 글은 고치지 말고, 어디가 어색하거나 부족한지 알려줘.
글: …
```

```text
$humanize-sepia 하고 싶은 말과 실제 있었던 일은 유지해줘.
글의 구성부터 새로 잡아서 처음부터 다시 써줘.
글: …
```

다듬은 뒤 “두 번째 문단만 더 짧게 해줘”처럼 이어서 요청할 수도 있습니다. 가장 최근 글에서 지정한 부분만 다시 다듬고, 나머지는 유지합니다.

## 마음에 든 수정 활용하기

전에 고친 문장이나 좋아하는 글이 있다면 무엇이 마음에 들었는지 함께 알려 주세요. 마음에 들지 않았던 문장과 채택한 문장을 함께 주면 무엇을 강조하거나 덜어 냈는지도 참고할 수 있습니다. 실제로 선택한 수정과 그 이유 중 이번 글에 맞는 기준을 활용합니다. 예를 들어 “역량을 먼저 선언하기보다 내가 바꾼 부분이 먼저 보였으면 좋겠어”처럼 설명하면 됩니다. 참고 글의 경험과 숫자는 새 글에 가져오지 않습니다.

참고 글이 없어도 바로 사용할 수 있습니다. 예전 선호와 이번 요청이 다르면 이번 요청을 따릅니다. 다른 대화에서도 활용하려면 참고 글이나 기록 파일을 다시 제공해 주세요. 스킬 설치만으로 수정 기록이 자동 저장되지는 않습니다. 기록을 파일로 정리하고 싶다면 저장할 위치와 함께 요청할 수 있습니다.

## 비판적으로 검토하고 개선하기

기존 글을 더 엄격하게 살펴보고 고치려면 비판적 개선을 요청하세요. 독자의 입장에서 문항에 실제로 답했는지, 주장에 맞는 행동과 근거가 있는지, 앞뒤 설명이 어긋나지 않는지 짚습니다. 효과가 큰 부분부터 삭제하거나 합친 문장, 같은 자료로 풀어 쓴 대체 문장을 만들어 원문과 비교합니다. 수정한 뒤에는 지적한 부분이 해결됐는지 다시 검토합니다.

```text
$humanize-sepia 아래 글을 독자의 입장에서 비판적으로 검토하고 고쳐줘.
내가 전하려는 말이 잘 드러나는지, 주장에 근거가 충분한지,
앞뒤 설명이 어긋나지 않는지 먼저 살펴봐.
수정한 뒤 지적한 문제가 해결됐는지 다시 확인해줘.
사실과 말투는 유지해줘.
글: …
```

지적이 타당한지 먼저 확인하고 필요한 수정을 합니다. 예를 들어 “성과 수치가 없어 약하다”는 의견이 있어도, 문항에서 수치를 요구하는지부터 살핍니다. 확인된 동료의 반응으로 충분히 답할 수 있다면 이를 쓰고, 측정하지 않은 성과를 만들어 넣지 않습니다.

이미 받은 검토 의견도 함께 보낼 수 있습니다. 어느 문장에서 어떤 이해가 막히는지 확인하고 실제 수정 문장으로 연결합니다. “더 인상적으로” 같은 총평만으로 글 전체를 바꾸지는 않습니다. 틀린 내용이 없어도 강조와 연결을 더 분명하게 만드는 대안을 비교할 수 있으며, 대안이 더 낫지 않으면 원문을 유지합니다. 검토만 요청하면 글을 고치지 않고 실제 문제와 선택 가능한 제안을 구별해 알려 줍니다.

구성까지 바꿔도 된다면 중요한 근거와 설명 순서가 다른 글을 비교할 수 있습니다. 각 글의 좋은 부분을 모두 붙이기보다, 전하려는 핵심에 필요한 내용만 골라 다시 씁니다. 원문과 비교해 나아진 부분을 확인하며, 표현만 고치는 요청에서는 지정한 범위를 지킵니다. 두 가지 안을 보여 달라고 요청하면 하나로 합치지 않고 각 안을 제공합니다.

별도 검토자를 사용할 수 있는 환경에서는 “새 문맥에서 독자의 입장으로 검토해줘”라고 요청할 수도 있습니다. 작성 과정의 자기평가 대신 요청·원자료·초안을 전달해 검토합니다. 같은 문맥에서 다시 읽은 경우나 AI가 가정한 독자 반응을 실제 독자의 평가로 표현하지 않습니다.

수정한 뒤에는 지적한 문제가 해결됐는지와 기존의 중요한 내용·사실·말투가 유지됐는지를 따로 확인합니다. 유효한 수정은 채택하고, 일부 변경이 잘못됐다면 그 부분을 복구합니다. 글 전체가 더 나빠졌다면 이전의 확인된 글로 돌아갑니다.

기본은 한 차례 검토·수정·재검토입니다. 해결할 수 있는 중요한 문제가 남았을 때만 반복하며, 별도 요청이 없으면 최대 세 차례 수정합니다. 충분히 좋은 글은 그대로 둡니다. 꼭 필요한 정보가 없거나 더 좋아지지 않으면 그 이유를 밝히고 멈춥니다. 반복 횟수나 자체 점수 상승을 글의 완성 기준으로 삼지 않습니다.

본문을 먼저 보여 주고, 왜 고쳤는지나 무엇을 확인해야 하는지 짧게 덧붙입니다. 사용자가 지정한 출력 형식이 우선입니다. 완성한 글에서도 실제 경험과 숫자는 확인해 주세요. AI 탐지기 점수는 글의 완성도를 판단하는 기준으로 쓰지 않습니다.
