# Humanize Sepia

[English](README.md) · [한국어](README.ko.md)

**뒤섞인 자료에서 원하는 바를 읽고, 자연스러운 한국어 글을 만드는 스킬.** 기업 정보·문항·방향성·초안을 순서 없이 붙여 넣어도 작성 의도를 파악합니다. 자기소개서는 기업·직무 맥락에서 문항이 실제로 확인하려는 역량과 판단을 읽고, 내 경험으로 그에 답하도록 작성합니다. 기존 글의 윤문과 진단도 지원합니다.

현재 버전은 **0.1.0**입니다. 지침과 예시는 한국어를 중심으로 작성돼 있으며, 필요한 작성 기준은 `humanize-sepia` 폴더 안에 포함돼 있습니다.

## 하는 일

| 모드 | 용도 |
|---|---|
| `write` | 자료·방향·초안을 함께 읽고 독자와 문항의 목적에 맞는 답변 작성 |
| `refactor` | 기존 논지·사실·말투·사건 순서를 유지하며 윤문 |
| `review` | 글을 고치지 않고 진단하며, 실제 문제와 선택 가능한 제안 구분 |
| `recreate` | 전면 개작을 명시적으로 요청한 경우, 사실과 의도를 유지하며 새 구조로 작성 |

문항의 단어를 하나씩 되풀이하는 대신, 평가자가 판단할 수 있는 행동과 근거를 고릅니다. “다른 시각”을 묻는다면 무엇을 다르게 보았고 왜 그 방법을 택했는지 보여 줄 수 있습니다. 분량·사례 수·필수 하위 질문처럼 명시한 요구는 지킵니다.

보여 주고 싶은 역량과 실제로 한 행동을 구분하고, 본인의 행동·타인의 승인·팀 성과의 범위를 유지합니다. 중요한 사실이 부족하면 필요한 부분만 묻거나 잠정 초안을 제공합니다. 보완 안내는 자기소개서 본문 밖에 둡니다.

## Codex 설치

Codex에서 다음과 같이 설치를 요청하세요.

```text
$skill-installer https://github.com/yeomin4242/humanize-sepia/tree/main/skills/humanize-sepia
```

직접 전역 설치하려면 저장소를 받은 뒤 스킬 폴더를 복사합니다. 같은 이름의 `humanize-sepia` 폴더가 이미 설치돼 있다면 먼저 다른 위치에 백업해 두세요.

```bash
git clone https://github.com/yeomin4242/humanize-sepia.git
mkdir -p ~/.agents/skills
cp -R humanize-sepia/skills/humanize-sepia ~/.agents/skills/
```

프로젝트에서만 쓰려면 해당 프로젝트의 `.agents/skills/humanize-sepia`에 스킬 폴더를 넣습니다.

## 사용법

`$humanize-sepia`로 호출하고 자료를 자유롭게 붙여 넣으세요. 기업 소개·직무·문항·쓰고 싶은 방향·경험·초안이 섞여 있어도 됩니다. **정해진 순서나 필수 항목명은 없습니다.** “쓰고자 하는 방향” 한 항목으로 적어도 되고, 제목 없이 이어 써도 됩니다.

아래 기업과 경험은 사용법을 보여 주기 위한 가상 예시입니다.

```text
$humanize-sepia

과장 없이 담담하게, 공백 포함 500자 이내로 써줘.
지원 회사는 소규모 판매자를 위한 온라인 장터를 운영하고,
운영 직무는 판매자 문의를 처리하고 반복되는 불편을 개선한대.

초안은 “저는 남다른 관찰력으로 기존의 틀을 깨는 사람입니다.
매장에서 문의를 정리하며 혁신적인 개선을 이루었습니다.” 정도야.
너무 거창해서 내가 실제로 한 일로 설득하고 싶어.

문항은 “익숙한 방식에서 벗어나 문제를 해결한 경험을 설명해 주세요.”
매장에서 알바할 때, 답이 담당자마다 달라서 손님이 다시 묻곤 했어.
나는 자주 오는 문의를 모아 답변표 초안을 만들었고,
매니저가 확인한 뒤 교대자들이 함께 쓰기 시작했어.
이후 교대자가 답을 찾기 편해졌다고 했어. 재문의 건수는 측정 안 했어.
새 프로그램을 만든 건 아니고, 문제를 응대 속도보다 답변의
일관성에서 본 점을 보여 주고 싶어. 회사 슬로건은 억지로 넣지 말아줘.
```

초안이 있어도 자료와 방향에 맞춰 답변을 완성해 달라고 하면 함께 재료로 씁니다. 잘 쓴 문장과 말투는 살리고, 최신의 명시한 방향을 따릅니다. 소재나 핵심 사실이 달라질 모호성만 확인합니다.

기존 글을 작업할 때는 원하는 범위를 지정하세요.

```text
$humanize-sepia 원문을 최소한으로 다듬어줘. 수치와 직접 인용은 유지해줘.
원문: …

$humanize-sepia 진단만 해줘. 실제 문제와 선택 가능한 개선을 구분해줘.
원문: …

$humanize-sepia 사실과 핵심 메시지를 유지하면서 전면 개작해줘.
원문: …
```

기본은 본문을 먼저 보여 주고, 중요한 수정 이유나 확인 사항만 짧게 덧붙입니다. 사용자가 지정한 출력 형식이 우선입니다. 작성자는 본인의 사실을 확인해야 하며, AI 탐지기 점수를 글의 완성 기준으로 삼지 않습니다.
